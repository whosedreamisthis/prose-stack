# Feature History

- **Database Setup (Prisma 7 + Neon):** Added Prisma 7 with the `@prisma/adapter-neon` driver adapter. `prisma/schema.prisma` uses the `prisma-client` generator (output `generated/prisma`, git-ignored, built by `postinstall`) with a URL-less datasource; `prisma.config.ts` takes the direct `DATABASE_URL_UNPOOLED` for the CLI and migrations. `lib/db.ts` exports one `server-only` client on the pooled `DATABASE_URL`, cached on `globalThis` outside production. First migration `init_user` contains only the `User` model and its `[isDemo, demoExpiresAt]` index, applied to the Neon `development` branch (the `production` branch is untouched); later features add their own models. Vitest is configured with the `@/` alias and node environment, with a shared `test/mock-prisma.ts` and a smoke test in `lib/users.test.ts`, so tests never reach Neon. `prisma` is pinned to 7.x because npm's default is an 8.0 release candidate. `.env.example` is committed with empty values. Specs now call the Neon dev branch `development`. Vercel still needs `npx prisma migrate deploy && next build` as the build command, with both DB env vars scoped per environment.

- **Authentication (Clerk Sign-in & Registration):** Added Clerk (`@clerk/nextjs` 7) with email/password and Google sign-in. `/sign-in` and `/register` live in the `app/(auth)` route group using Clerk's `SignIn`/`SignUp`. `proxy.ts` (Next.js 16's rename of middleware) protects everything except `/`, the auth pages and `/api/webhooks/clerk`; signed-out requests redirect to `/sign-in`. The root layout puts `ClerkProvider` inside `<body>` and wraps auth-reading parts in `<Suspense>`, which `cacheComponents: true` requires. The navbar shows Clerk's `UserButton` via `<Show when="signed-in">` (Clerk 7 removed `SignedIn`), and `/` redirects signed-in users to `/projects` (a placeholder page until the Projects feature). `/api/webhooks/clerk` verifies with `verifyWebhook` and upserts on `user.created` or deletes on `user.deleted`, returning 500 on DB errors so Clerk retries. `lib/users.ts` holds Zod-validated upsert/delete helpers; `lib/auth.ts` `getCurrentUser()` creates the `User` on first request if the webhook has not arrived. No new migration. Vitest covers the webhook, fallback and helpers. Not verified: a real sign-up, Google sign-in, or a signed webhook delivery; `CLERK_WEBHOOK_SIGNING_SECRET` was not yet set. Known gaps: a missing signing secret returns 400 instead of 500, `user.updated` is not synced, a unique-email conflict would make the webhook retry, and unauthenticated API calls get a redirect instead of a 401.

- **Projects:** Added multiple books per user. Migration `add_project` creates `Project` (cover design and color, formatting-setting defaults, nullable `lastOpenedAt`) with a cascade foreign key from `User`. `actions/projects.ts` has `createProject`, `deleteProject` and `markProjectOpened`, all Zod-validated and scoped to the signed-in user; project ids are validated too. Creation is capped at 5 projects per user (`MAX_PROJECTS_PER_USER`), checked inside a transaction that first locks the user row (`FOR UPDATE`), because without the lock 8 simultaneous creates all succeeded in a real-database test. `markProjectOpened` uses raw SQL so opening a project does not bump `updatedAt` (which means "last edited"). `lib/projects.ts` has the list, get and last-opened-landing queries. `/projects` shows cover cards with a delete menu and confirmation, the new-project dialog has a live cover preview (four designs, eight colors plus a picker), and the navbar has a project switcher that reads the current project from the URL. `/projects/[projectId]/manuscript` is a placeholder until the Manuscript feature. Signed-in visitors skip the landing page: `proxy.ts` redirects `/` to `/continue`, a route handler that redirects to the last-opened project or `/projects`. Also added shadcn/ui (`base-nova`, Base UI), Zustand, Sonner toasts, a dark root, `<ClerkProvider dynamic>` inside `<Suspense>` (fixes a `UserButton` hydration error under Cache Components), a corrected `proxy.ts` matcher (a single-backslash typo let URLs containing text like `png` or `js` skip Clerk's middleware), React `cache()` on `getCurrentUser()`, UTC date formatting, and Vitest `mockReset`. The README now credits Dabble Writer as the inspiration. Decisions: delete is permanent after confirmation, 5-project limit, sign-in lands on the last-opened project. Deferred: seeding Chapter 1 / Scene 1, UploadThing cover upload, per-project word count, settings-modal editing, demo limits. Known gaps: opening another user's project shows the not-found page with HTTP 200 because the page streams; `ActiveProjectSync` still writes a store field nothing reads; the unused shadcn `textarea` is installed; the `/` to `/continue` redirect is not unit-tested; delete, the color picker and phone layout were not clicked through by hand; and the migration reaches production on the first Vercel build after this merge.

- **Sidebars & Layout:** Added the project shell. `app/projects/[projectId]/layout.tsx` renders `ProjectShell` (a client component) around every project page; `/projects`, `/` and the auth pages stay outside it. The left and right sidebars are fed by Next.js parallel routes (`@left`, `@right`, each with a `default.tsx` returning null), so each page supplies its own panel; the manuscript page provides a placeholder outline and a "Scene details" panel. Each slot sits in its own `<Suspense>` in the layout because Next.js resolves slots at request time under Cache Components, and without it the dev-only "Instant" check reported uncached data; this was found by elimination using a headless Chrome signed in as the developer through a single-use Clerk sign-in token, which also showed that the error never appeared signed out. The left sidebar collapses to 0px and becomes `inert`, and below `md` it is a drawer (a Base UI `Sheet`) opened by a separate button, so CSS picks desktop or mobile with no viewport detection; `leftOpen` and `drawerOpen` are separate store fields for that reason. The right sidebar shows from `lg` up and its toggle is disabled until a page mounts `RightPanel`. Sidebar state lives in `lib/stores/layout-store.ts` (session only, not persisted, per the spec decision) with unit tests. `EditorColumn` provides breadcrumbs, a toolbar of six disabled stubs, the writing area, and a stats footer. There is one navbar: `ProjectNavActions` adds disabled Spell check, Export to PDF and Settings stubs only on project routes. Icons are 20px, disabled stubs are drawn at 70% opacity, and ghost and outline buttons now set `text-foreground` (they had no text color, so icons rendered dark on the dark background). Dark stays the default theme. Verified in a signed-in browser: collapse and expand of both sidebars, state surviving navigation through the switcher, the mobile drawer closing on Escape with focus returned, zero console errors, and layout shift 0.039 on a hard load (dev). Known gaps: no right sidebar between 768 and 1023px, the drawer title is the generic "Project", shell behavior has no automated test beyond the store, `title` tooltips do not show on disabled buttons in some browsers, and the stats footer, tree and scene panels are placeholders. Deferred: a per-project accent color derived from the cover color (accent only, inside projects, lightened for contrast, injected as a streamed `<style>` plus a short fade), to be its own feature.
