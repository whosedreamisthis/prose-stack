# Feature History

- **Database Setup (Prisma 7 + Neon):** Added Prisma 7 with the `@prisma/adapter-neon` driver adapter. `prisma/schema.prisma` uses the `prisma-client` generator (output `generated/prisma`, git-ignored, built by `postinstall`) with a URL-less datasource; `prisma.config.ts` takes the direct `DATABASE_URL_UNPOOLED` for the CLI and migrations. `lib/db.ts` exports one `server-only` client on the pooled `DATABASE_URL`, cached on `globalThis` outside production. First migration `init_user` contains only the `User` model and its `[isDemo, demoExpiresAt]` index, applied to the Neon `development` branch (the `production` branch is untouched); later features add their own models. Vitest is configured with the `@/` alias and node environment, with a shared `test/mock-prisma.ts` and a smoke test in `lib/users.test.ts`, so tests never reach Neon. `prisma` is pinned to 7.x because npm's default is an 8.0 release candidate. `.env.example` is committed with empty values. Specs now call the Neon dev branch `development`. Vercel still needs `npx prisma migrate deploy && next build` as the build command, with both DB env vars scoped per environment.
