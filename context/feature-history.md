# Feature History

- **Database Setup (Prisma 7 + Neon):** Added Prisma 7 with the `@prisma/adapter-neon` driver adapter. `prisma/schema.prisma` uses the `prisma-client` generator (output `generated/prisma`, git-ignored, built by `postinstall`) with a URL-less datasource; `prisma.config.ts` takes the direct `DATABASE_URL_UNPOOLED` for the CLI and migrations. `lib/db.ts` exports one `server-only` client on the pooled `DATABASE_URL`, cached on `globalThis` outside production. First migration `init_user` contains only the `User` model and its `[isDemo, demoExpiresAt]` index, applied to the Neon `development` branch (the `production` branch is untouched); later features add their own models. Vitest is configured with the `@/` alias and node environment, with a shared `test/mock-prisma.ts` and a smoke test in `lib/users.test.ts`, so tests never reach Neon. `prisma` is pinned to 7.x because npm's default is an 8.0 release candidate. `.env.example` is committed with empty values. Specs now call the Neon dev branch `development`. Vercel still needs `npx prisma migrate deploy && next build` as the build command, with both DB env vars scoped per environment.

- **Authentication (Clerk Sign-in & Registration):** Added Clerk (`@clerk/nextjs` 7) with email/password and Google sign-in. `/sign-in` and `/register` live in the `app/(auth)` route group using Clerk's `SignIn`/`SignUp`. `proxy.ts` (Next.js 16's rename of middleware) protects everything except `/`, the auth pages and `/api/webhooks/clerk`; signed-out requests redirect to `/sign-in`. The root layout puts `ClerkProvider` inside `<body>` and wraps auth-reading parts in `<Suspense>`, which `cacheComponents: true` requires. The navbar shows Clerk's `UserButton` via `<Show when="signed-in">` (Clerk 7 removed `SignedIn`), and `/` redirects signed-in users to `/projects` (a placeholder page until the Projects feature). `/api/webhooks/clerk` verifies with `verifyWebhook` and upserts on `user.created` or deletes on `user.deleted`, returning 500 on DB errors so Clerk retries. `lib/users.ts` holds Zod-validated upsert/delete helpers; `lib/auth.ts` `getCurrentUser()` creates the `User` on first request if the webhook has not arrived. No new migration. Vitest covers the webhook, fallback and helpers. Not verified: a real sign-up, Google sign-in, or a signed webhook delivery; `CLERK_WEBHOOK_SIGNING_SECRET` was not yet set. Known gaps: a missing signing secret returns 400 instead of 500, `user.updated` is not synced, a unique-email conflict would make the webhook retry, and unauthenticated API calls get a redirect instead of a 401.
